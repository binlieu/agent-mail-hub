Examples & prompts

Set up two real AI sessions, give each a role, and follow the messages and evidence in your dashboard.

These are copyable exercises, not recorded run results. The page does not run commands, start models or send messages. You run the setup and paste each prompt into the named Claude or Codex session. Your AI subscription usage applies when you run a model.

Setup once

Use the running hub or create a separate sample hub. Run terminal commands from the package folder with Node.js 24.6+. Replace /absolute/path/sample-hub with a new private directory. Port 47941 is an example: choose another if occupied; never stop another service to take its port.

Terminal — only if you need a separate hub
npm ci
npm run build
node dist/cli.js setup --data-dir /absolute/path/sample-hub --port 47941
node dist/cli.js start --data-dir /absolute/path/sample-hub

Keep the hub terminal running. If reusing a hub, skip those commands and use its actual data directory in every setup block. In a second terminal, register the two agents for the case you choose below. The role names are hub identities, not model selectors.

  1. Register only your chosen case's pair. Both must share the case's project. Names are unique hub-wide; for a rerun use new names (update every prompt), or reuse the original private credentials for the same sessions.
  2. For each printed credential path, run the configuration command below. Attach that agent's MCP configuration only to its intended AI session, following How to use, steps 3–4. Keep existing A2A entries and global settings intact. Roles do not require changing a model.
  3. In each AI session, paste the connection check below. If the tools are unavailable or the peer is missing, resolve configuration before starting the exercise. A heartbeat proves adapter connectivity, not model activity.
  4. Choose a new run key such as practice-001. Replace every RUN_ID in that exercise with it. Reuse the same key for an identical retry; use a new run key for a new assignment.
Terminal — generate one config per credential
node dist/cli.js config --credentials /absolute/path/printed-agent-credential.json
Both AI sessions — replace YOUR_NAME and PEER_NAME
For this exercise, your Agent Mail Hub identity is YOUR_NAME and your peer is PEER_NAME. Use only the agent-mail-hub MCP server for inter-agent communication. Call list_agents and confirm both names are visible in the same project. Report your configured identity and the observed directory; do not impersonate another sender. If the expected tools or peer are missing, stop and tell me what is missing. During this connection check only, do not change global settings, existing A2A, files or credentials. Do not start subagents.
Delivery is pull-based. Paste the next role's prompt yourself; sending a message does not wake the other AI. In every case, read inbox pages with after: 0, limit: 100 initially; if needed, advance using nextCursor until the expected run is found or the inbox is exhausted. Stop if it is absent. Acknowledge after receipt and durable handling. Never invent IDs, checksums, test results or permission.

CASE 1 · DELEGATE AND VERIFY

Codex as PM, Claude as worker

Codex prepares a bounded assignment. Claude independently checks a supplied total and returns a new result artifact. Codex verifies the returned evidence. This starter case requires only the hub's MCP tools; it changes no source files.

Terminal — register the pair
node dist/cli.js add-agent --data-dir /absolute/path/sample-hub --name codex-pm --project sample-codex-pm --provider codex --model default
node dist/cli.js add-agent --data-dir /absolute/path/sample-hub --name claude-worker --project sample-codex-pm --provider claude --model default
1 → Codex PM
You are codex-pm. I authorize this bounded hub-only exercise. Prepare work for claude-worker; do not solve the worker's task first. Upload fixture.json using upload_evidence with mediaType application/json, encoding utf8, content exactly {"values":[230,87,100],"declaredTotal":418}, sourceRef sample://RUN_ID/fixture.json and idempotencyKey RUN_ID-pm1-fixture.
Use the returned evidence ID in create_handoff to claude-worker. Set objective "RUN_ID: independently verify the declared total", context "Use the supplied immutable fixture only. Return the actual calculated total and whether it matches. No filesystem or external actions.", completed ["Prepared input fixture; total not verified"], remaining ["Independently sum values and compare declaredTotal"], nextSteps ["Fetch and review evidence", "Accept, calculate and upload new result.json", "Complete with the result evidence"], workspaceRef sample://RUN_ID, evidenceIds [the real fixture ID], idempotencyKey RUN_ID-pm1-offer.
Report the real handoff ID, evidence ID and returned SHA-256. Stop after offering. No commits, configuration changes or other agents.
2 → Claude worker
You are claude-worker. I authorize only this arithmetic exercise through agent-mail-hub. Read your inbox and find codex-pm's RUN_ID handoff. Get its real handoff ID, then call get_handoff and get_evidence with includeContent true for every input. Read the actual content. Compare checksum metadata; if you cannot independently hash bytes, say so instead of claiming independent checksum verification. Call review_evidence for each input with state reviewed, the observed SHA-256 and a truthful note.
Accept with update_handoff using state accepted, a note and idempotencyKey RUN_ID-pm1-accept. Independently calculate the sum. Upload NEW result.json, mediaType application/json, encoding utf8, sourceRef sample://RUN_ID/claude-result.json, idempotencyKey RUN_ID-pm1-result. Include sourceEvidenceId, sourceSha256, calculatedTotal, declaredTotal and matches from the actual input and calculation.
Complete the accepted handoff with update_handoff state completed, a truthful note, evidenceIds [your new result ID] and idempotencyKey RUN_ID-pm1-complete. Acknowledge the original message after handling it. Report actual IDs and stop. Do not change files or claim tests, commits or deployment.
3 → Codex PM
Read your inbox and get the RUN_ID handoff you offered to claude-worker. Fetch its new completion evidence with get_evidence. Check the calculation against the original fixture independently. Record review_evidence on the result with a truthful checksum/content review note; use rejected if the result is wrong. Acknowledge the worker's acceptance/completion notifications after reviewing them. Report the actual handoff state, message IDs, input/result evidence IDs, actual versus declared total, and what you independently checked. Stop; a completed handoff is not proof of tests, commits or deployment.

Expected check: calculated total 417, declared total 418, matches: false. In the dashboard, filter sample-codex-pm and inspect Handoff: completed, result evidence and PM review receipts. This is an expected outcome, not a claim this page ran it.

CASE 3 · IMPLEMENT, REVIEW, FIX

Claude as code reviewer, Codex as coder

This exercise deliberately starts with a small bug. Codex creates and tests two files in a new scratch directory; Claude reviews the transferred source and test evidence; Codex fixes the bug and reruns the tests. Replace /absolute/path/isolated-review-RUN_ID everywhere with a fresh, dedicated scratch path before pasting. These prompts directly authorize that sample scope; they do not authorize changes in a real repository.

Terminal — register the pair
node dist/cli.js add-agent --data-dir /absolute/path/sample-hub --name codex-coder --project sample-code-review --provider codex --model default
node dist/cli.js add-agent --data-dir /absolute/path/sample-hub --name claude-reviewer --project sample-code-review --provider claude --model default
Exact sample files and test command
// total.mjs — deliberately missing the empty-array initial value
export function total(values) {
  return values.reduce((sum, value) => sum + value);
}

// total.test.mjs
import test from 'node:test';
import assert from 'node:assert/strict';
import { total } from './total.mjs';
test('empty input', () => assert.equal(total([]), 0));
test('fixture input', () => assert.equal(total([230, 87, 100]), 417));
test('negative values', () => assert.equal(total([-2, 5]), 3));

// Run in the scratch directory: node --test total.test.mjs

A handoff transfers a packet and evidence copies. It does not transfer provider memory, tokens, account allowance, shell permissions or ownership of a running process. Adapt the checkpoint for a real coding job

Replace the arithmetic fixture with a factual checkpoint: objective, exact workspace/worktree and branch, current commit, dirty files, completed/remaining items, actual commands and results, blockers and next steps. Include original source paths and immutable copies of the relevant code, diff and logs. Record missing facts as unknown. A path is provenance, not a transferred file. Copies are limited to 64 KiB each and ten per handoff; larger materials need a manifest with original locations and hashes. The human must separately authorize the recipient's real workspace and actions. Never include credentials or provider tokens.

What to inspect after a run

Use View conversation for the message trail and Handoff: completed for the packet, review receipts and new result evidence. Downloads check transferred bytes in your browser. If the recipient is idle, paste its next prompt; if delivery is paused, resume it in the dashboard. A missing tool, scope approval or model limit is a blocker to report, not permission to bypass it. When adapting these examples to code, wait for the owner's tested/commit signal before committing.

For an optional real Claude/Codex smoke test, the package also includes node scripts/live-e2e.mjs --handoff --hub-data-dir /absolute/path/sample-hub. Running that command uses your signed-in CLI accounts, creates fresh test identities and retains private evidence. It exercises the arithmetic handoff, not all four cases on this page.
